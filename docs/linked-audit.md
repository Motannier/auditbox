# 关联审计与操作追溯

关联审计用于查清哪个账号在什么时间、哪台设备上提交了什么命令，命令经过怎样的审批，以及是否实际下发。Agent 操作还会关联原问题、对话和运行记录，便于沿一次任务回查操作经过。

超级管理员可在工作台查看和导出审计。记录按登录账号归属操作；多人共用账号时，无法仅凭这些记录区分具体操作人。

## 怎样理解一条操作记录

| 记录 | 回答的问题 |
| --- | --- |
| 登录 | 哪个账号通过了认证，后续操作关联哪次登录 |
| 命令执行与输入详情 | 在哪个终端、对哪个目标提交了什么命令，来自人工还是 Agent |
| 行为 | 是否请求确认、批准、取消或阻断，是否连接或断开终端 |
| 下发状态与输出摘要 | 命令是否实际发给设备，返回了哪些可保留的输出 |
| 旁路审查 | 规则或模型给出了什么风险建议，依据哪些历史命令 |

命令已提交、已批准、已下发和成功完成分别记录。缺少可靠退出码时，通过提示符推断的结果保留为未知；终端断开也不等同于执行成功或账号登出。风险提示描述潜在影响，不能单独证明操作造成了破坏。

一条实际提交的命令对应一条执行记录与一条输入详情，确认请求、批准和下发状态持续更新同一条记录。重复提交的同名命令分别保存。速查填入和普通按键不计为命令执行。

## 账号、终端与 Agent 怎样关联

签名凭证携带成功登录记录的 ID，刷新凭证时保留该关联。旧凭证或旧连接缺少登录记录时，关联字段留空；登录记录目前没有登出或登录结束时间字段。

人工和速查来源展示为手动输入。Agent 的已验证账号、聊天 ID、运行轮次、原问题与操作目的，通过与命令相同的有序输入帧传递；浏览器不能自行注入审计上下文或冒充 Agent 输入。工具审批与命令二次确认分别记录为行为。

Agent 的固定本地用户用于保存对话，浏览器登录账号用于关联终端审计，两者作用不同。具体执行过程见 [共享终端工具设计](../agent/docs/TERMINAL_TOOL_DESIGN.md)。

## 输出保留与脱敏

命令输出先合并，在静默时写入脱敏摘要，最多保留末尾 16,000 字符。浏览器终端收到的设备数据保持原样。摘要可能包含命令回显或异步输出，不能作为完整终端录像使用。

脱敏覆盖敏感字段和常见命令凭据语法，无标识的秘密仍可能出现在设备输出中。导出前需核对内容，并按业务数据管理备份。新记录不保存普通按键原文和原始终端输出字节；历史 JSONL 原文保持原样。

Proxy 启动时会恢复未完成执行的状态。规则与模型审查沿各自链路运行，审计记录其决策和结果；旁路审查不会据此锁定终端。

## 存储与增量读取

业务 SQLite 保存以下表，具体实现见 [store.py](../box/auditbox/audit/store.py)：

| 表 | 内容 |
| --- | --- |
| `audit_logins` | 登录记录 |
| `audit_executions` | 命令执行及其状态 |
| `audit_inputs` | 与执行关联的输入详情 |
| `audit_behaviors` | 审批、连接、审查等行为 |
| `audit_changes` | 与业务记录在同一事务提交的递增变更 |

管理接口按游标读取新增与更新。JSONL 保留兼容记录；systemd 部署的 SQLite 位于 `/var/lib/auditbox-server/`，JSONL 位于 `/var/log/auditbox-server/`，QuickStart 的数据与日志位于 `box/data/`。

### 实例身份

`box_info` 保存稳定的 `box_id` 和 `last_system_update_at`。读取到有效 CPU 序列号时，`box_id` 使用其小写十六进制原文：优先读取 `/proc/cpuinfo` 的 `Serial`，其次读取内核 SoC 设备的 `serial_number`。设备树的板卡序列号不作为 CPU 身份来源。

读取不到有效序列号时保留已有 ID，仅在首次初始化时生成兼容 ID。升级将旧生成 ID 保存在 `box_identity_aliases`，通过 `legacy_box_ids` 返回，供管理端沿用原档案、历史关联和同步游标。迁移会更新记录中的设备标识并追加修订；原始变更日志保留，导出旧修订时映射到新标识。

新硬件部署应独立初始化数据库。已保存的 CPU 序列号与当前硬件不符时，初始化会被拒绝。

## 历史 JSONL 转换

现有 JSONL 可转换为关联记录。先确认实例身份，关闭活动终端，并备份 SQLite 与原 JSONL，再由具有数据库读写权限的服务账号预览转换计划。systemd 部署示例：

```bash
sudo -u auditbox-server env \
  PYTHONPATH=/opt/auditbox-server/current/box \
  AUDITBOX_DB_PATH=/var/lib/auditbox-server/auditbox.sqlite3 \
  /opt/auditbox-server/current/box/.venv/bin/python \
  -m auditbox.audit.legacy --directory /var/log/auditbox-server
```

核对预览结果后，在同一命令末尾添加 `--apply` 执行转换。本地开发使用相应虚拟环境、`AUDITBOX_DB_PATH` 和日志目录。转换不会删除原 JSONL；审计存储初始化仍会检查表结构与实例身份。

- 旧数据只按已有登录事实和聊天标识关联，缺失字段留空。来源未记录时为 `unknown`，缺少可靠结果时仍为未知。
- 终端连接、速查、确认和旁路审查转为行为记录。输出按旧事件顺序归入命令，脱敏并限制摘要长度；完整历史可在原文件中核对。
- ID 由实例、会话和记录位置派生，`audit_legacy_imports` 保存来源 SHA-256 与转换版本。记录、变更日志和检查点在同一事务提交，重复转换不重复插入；已转换原文发生变化时报错。
- 已有新版记录的会话会跳过，避免重复转换。
