# 交换机执行确认规则

此目录提供交换机执行前二次确认和旁路规则评估所需的数据。规则处理不调用模型；Linux 原有模型与风险处理链路，以及推荐策略、指令速查和行为图均保持不变。

## 数据与再生成

压缩数据来自已整理的 `命令提取/review_v3/risk_export` 四份品牌 JSON。
在仓库根目录运行：

```sh
node tools/build_switch_risk.mjs /实际路径/命令提取/review_v3/risk_export
```

生成脚本仅更新此目录，不修改输入资料。`manifest.json` 记录源文件与运行数据的 SHA-256、条数和策略版本。这些文件是运行必需资源，部署时须随 `auditbox/security` 复制。

| 设备子类型 | 全部命令形式 | 有风险（含待核对） | 无风险 | 待核对 |
| --- | ---: | ---: | ---: | ---: |
| 华三 `h3c_comware` | 18,028 | 14,625 | 3,403 | 180 |
| 华为 `huawei_vrp` | 31,736 | 25,716 | 6,020 | 339 |
| 思科 `cisco_ios` | 2,286 | 1,562 | 724 | 288 |
| 中兴 `zte_zxr10` | 12,673 | 10,211 | 2,462 | 452 |

表中按命令的参数形式计数，同一命令族可有多条。待核对记录包含源资料中的 1,258 条，以及中兴 `show ip protocol routing` 的一条尖括号/重定向歧义记录，共 1,259 条；该歧义形式仍需确认。

压缩 JSON 使用字符串表；每条记录为：

```text
[id, 命令族索引, 语法索引, 状态, 原因索引, 型号摘要索引, 视图摘要索引, 来源摘要索引]
状态：0 = 已整理为无风险，1 = 有风险，2 = 待核对
```

型号和视图摘要用于追溯，具体命令是否适用仍须核对设备型号和当前视图。思科资料包含 NX-OS，设备子类型标识仍为 `cisco_ios`；资料覆盖范围以实际整理内容为准，不能扩展到所有 IOS/NX-OS 版本。

## 执行策略

- 硬阻断规则优先，确认不能解除阻断；其余风险与待核对形式需要确认。
- 已核验只读形式直接放行；未命中风险或待核对规则的未知命令也直接放行，包括 `ls`、未收录的缩写，以及未匹配已知风险分支的参数。未知放行时，风险仍未经核验。
- 命中风险/待核对命令族、复合命令、写文件管道，或规则缺失、校验失败时，需要确认。未知放行仅适用于规则正常且命令未收录的情况。
- 语法匹配器仅解析有限的手册语法，设置长度、嵌套、重复与计算量边界；不支持的语法不扩展成任意参数通配符。
- 同一命令族同时包含无风险与有风险形式，且无法可靠区分时，需要确认。可明确区分的参数分支单独处理，如中兴 `show cos-queue ... clear`、华三交互 `monitor` 与固定 `dumbtty`、公钥显示与文件导出。
- 查询过滤与已核验视图导航保留；待核对优先于只读白名单或导航特例，不会被更细的命令族覆盖。例如华为 `system-view [ immediately ]` 涉及待核对记录，其匹配形式仍需确认；中兴 `configure terminal` 涉及已整理为风险的事务模式语法，仍需确认。
- 主动探测、调试、采集、保存、配置和运行状态变更需要确认。华为 `format bulkascii` 按导出格式配置处理，不描述为磁盘格式化。
- 风险形式同时按标题与语法建立索引，避免将 `undo accept-lifetime` 等比手册标题更短的形式归为未知。思科设备名称/清除计数、中兴重启操作通过明确规则要求确认。

执行判定与审计分级分别处理。`confirmation_reason` 返回空表示允许执行；`command_policy` 区分 `read_only` 和 `unknown`。华为/思科/中兴的旁路结果将未知放行项记为 `risk=unknown, action=allow`，风险仍未知；资料中明确的待核对项使用 `action=confirm`。

规则通过 `security.alert.check` 接入共享的 `CommandGate`，沿用确认弹窗、一次性令牌、取消、硬阻断和审计记录。密码认证与传输协议保持不变。

H3C 推荐保留需确认项并标记 `confirm`，只过滤硬阻断项；执行限制不删减行为图。Linux 模型与代码路径保持不变。
