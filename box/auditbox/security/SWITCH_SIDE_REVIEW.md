# 交换机旁路审计

执行前二次确认与旁路风险评估独立运行。

| 设备子类型 | 执行前确认 | 近期历史的旁路评估 |
| --- | --- | --- |
| Linux | 命令规则与确认流程 | Linux 审查模型 |
| H3C / 华三 | 交换机规则：已知风险/待核对确认，未知放行 | H3C 专用模型，需另行配置并启用 |
| 华为 / 思科 / 中兴 | 对应品牌规则：已知风险/待核对确认，未知放行 | 对应品牌规则旁路审计 |

服务器默认仅启用 Linux 模型路由；华三专用模型需另行准备并启用对应路由。

华为、思科、中兴的旁路审计复用 `alert.check` 与已整理的命令数据，直接返回规则结果，取代 `unsupported` 状态。这条链路独立于 Linux/H3C 模型，不修改行为图、推荐、补全或速查。

## 规则等级

- `low`：执行规则已完整核验为只读或导航。
- `medium`：资料已确认涉及状态变更，但未命中高影响操作规则，例如创建 VLAN、保存配置、清除普通计数。
- `high`：资料已确认有风险，并命中重启、关闭/启用接口、删除网络对象、路由/端口转发变更、文件删除/格式化等规则。关键词只匹配操作位置；描述参数中出现 `reload` 不会单独提高等级。
- `critical`：命中单条命令阻断规则，旁路结果仍不锁定盒子。
- `unknown`：命令待核对、未收录、语法未经核验或规则不可用，风险尚未确定。规则正常但未收录的命令直接放行（`action=allow`）；命中待核对/风险分支、组合/写入语法，或规则不可用时，仍需确认（`action=confirm`）。

语法或命令族匹配会在每条结果中标注 `match_type`、`rule_id`、`command_family`。匹配结果仅反映规则命中情况，具体型号、视图和参数是否有效仍须核对。资料与模型的适用范围受原手册限制；思科资料包含 NX-OS，`cisco_ios` 标识不保证覆盖所有版本。

汇总显示审计窗口内已知的最高潜在风险、待核验项数量及证据，并分别统计未知放行和仍需确认的条数。结论依据规则匹配结果描述潜在影响，不推断用户动机或认定命令已造成破坏。

## 执行状态与审计边界

旁路结果逐条保留 `executed`、`blocked`、`cancelled`、`failed` 和单次授权标记。`executed` 表示命令已下发，最终效果以设备输出为准；取消和阻断表示未下发，设备报错表示效果尚未确认。单次授权不改变风险等级，也不会触发重复确认或自动锁定。

所有设备的旁路结果仅用于记录和展示风险，不锁定盒子或冻结终端。Linux 和已配置的 H3C 模型结果保留风险等级、原因、置信度和证据；旧模型输出中的 `lock=true` 会被忽略。规则结果使用兼容字段 `confidence=0`，不提供模型置信度。

执行前二次确认和单条命令阻断继续生效：被阻断的命令不下发，其他命令仍可操作；二次确认令牌仅授权本次操作。旁路结果不能取消待确认命令、清空输入、暂停指令队列、发送 Ctrl+C 或影响同一设备的其他会话。

旧 `terminal_locks` 表和记录保留用于历史追溯，运行时不加载、恢复或写入锁定状态。前端不显示锁定遮罩和管理员解锁按钮；网关丢弃旧客户端的 `session_unlock_debug` 控制消息，防止其被当作终端命令转发。兼容输出中的 `lock`、`locked`、`allow_lock` 始终为 false。旧 `AUDITBOX_HISTORY_REVIEW_LOCK_CONFIDENCE` 配置已停用。

升级时同步更新代理、网关和前端，重启相关服务并重新连接终端。旧后端进程中的锁须通过更新并重启后端解除，单独刷新前端无效。新后端不会恢复旧锁，历史数据库可继续保留。

## 队列和结果

规则审计使用独立后台线程，与 Linux/H3C 模型请求分别排队；历史窗口、合并间隔和 `AUDITBOX_HISTORY_REVIEW_ENABLED` 开关保持一致。设备报错后，规则和模型审计会重新提交带失败状态的快照，旧结果不能覆盖新状态。

`current` 表示当前命令的独立等级，顶层 `risk` 表示历史窗口结论。规则逐条评估，后续查询不能沿用窗口最高风险。Linux/H3C 模型在已有历史且当前命令结论缺失或非低风险时，会额外复核该条命令，同时保留窗口结论；复核失败显示未知。低风险结果不触发额外请求，历史窗口范围保持不变。

审查结果绑定会话、命令序号和快照令牌；网关和前端均检查递增版本，拒绝晚到的旧结论。排队时清除当前等级，保留已完成的历史逐条结果。执行日志按独立结果更新对应命令，窗口证据只关联行为记录，不批量覆写命令等级。

结果通过 `operation_review` 推送到所属终端，前端标明“规则引擎”或“H3C 专用模型/本地模型”。规则数据出错时显示中断/待核验，不显示低风险。

`security_rule_review` / `security_model_review` 写入所属会话的审计日志，记录等级和历史序号；规则结果另记策略版本和来源，模型结果保留置信度。审查事件不重复写入原始命令或凭据。会话隔离、确认令牌和推荐链路继续沿用现有机制。
